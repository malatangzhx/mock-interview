# AI 模拟面试

一个面向 AI 应用开发实习生的本地、隐私优先模拟面试原型。默认使用可解释的离线规则引擎，因此无需 API Key 即可完成从简历/JD 到面试报告的完整流程。

预设岗位包含“AI 应用开发实习生”和“数据分析师”。根据 MVP 的校准边界，前者为正式训练模式，后者提供独立的 SQL、统计、数据质量、可视化与业务分析题目基线，但仍标记为实验模式。

## 启动

Windows 用户推荐直接双击项目根目录中的 `start.bat`（也保留了中文文件名版本）。脚本会在首次运行时创建虚拟环境、安装依赖、启动服务并打开浏览器；之后启动不会重复安装。如果系统策略阻止自动打开浏览器，窗口会保留并显示 `http://127.0.0.1:8000`，复制到浏览器即可。

也可以手动运行：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py
```

打开 <http://127.0.0.1:8000>。面试页采用双窗口视频通话布局：本地候选人镜头与知性女性虚拟面试官“林老师”并排展示。连接 OpenAI 官方服务后，页面通过 WebRTC 建立原生语音到语音会话：麦克风持续聆听，语义 VAD 自动判断轮次，候选人无需确认或提交即可得到语音回应，并可随时插话。双方字幕在下方滚动展示。推荐使用最新版 Chrome 或 Edge 并佩戴耳机；设备或 Realtime 服务不可用时可切换文字模式。

## 面试前七步流程

面试前按“AI 接入 → 个人资料 → 目标岗位 → 本场题库 → 面试计划 → 面试调试 → 正式面试”推进。顶部步骤索引允许返回已完成步骤；修改资料后只使依赖它的推荐和计划失效，摄像头、麦克风等无关结果仍保留。

- AI 接入优先使用个人 API，也提供系统 AI（需服务端配置）和本地模式。高级地址、协议、流式和超时设置默认折叠。
- 简历与岗位分析都必须由用户主动触发，结果先进入可编辑确认态；缺少资料时可以跳过并使用通用画像。
- 题库推荐只给顺序和理由，不改变 4+2、专项模式、去重和来源快照等后端硬规则。
- 面试调试集中检查摄像头、麦克风音量、浏览器语音识别和模型结构化响应。开始按钮附近会列出尚未满足的条件；摄像头可二次确认后跳过，语音识别不可用时自动切换文字输入。

## AI 实时面试（可选）

语音接入按服务商能力分为两类：

- OpenAI 官方：固定使用 `gpt-realtime-2.1`，通过 WebRTC 原生语音到语音。
- 通义千问：填写百炼业务空间的 `.../api/v1/webrtc/realtime` 地址后，使用 `qwen3.5-omni-flash-realtime` 原生语音；只填写普通 DashScope 文本地址时自动降级为级联语音。
- DeepSeek：官方公开 API 当前是文本 Chat/SSE，使用浏览器实时转写 → DeepSeek → 系统自然音色的自动级联链路。
- 豆包：方舟文本 API Key 使用自动级联链路。豆包端到端 S2S 属于独立的豆包语音产品，需要另外申请 AppID、Access Key、App Key 和 Resource ID，不能把方舟单 Key 当作语音凭据。

所有模式都不要求用户确认字幕或手动提交；级联模式会在短暂停顿后自动提交本轮转写。标准 API Key 只保存在本机 FastAPI 进程内存中。原生模式的浏览器 SDP 由本机服务代理鉴权，长期密钥不会返回前端。推荐使用最新版 Chrome 或 Edge，并佩戴耳机降低回声。

其他服务商继续支持原有文字模型流程，并在 Realtime 不可用时作为降级路径。

在第一步“AI 接入”中启用个人 API，支持 OpenAI（Chat / Responses）、DeepSeek、通义千问、Claude、Gemini、Kimi、智谱 GLM、豆包、MiniMax、硅基流动及自定义兼容服务。选择服务商和模型并填入该平台签发的 API Key，再点击“测试并连接”；地址、协议、流式和超时设置位于折叠的高级设置中。所有预设均可编辑，列表是示例，并不保证账户有对应模型权限。

协议支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；Gemini 使用 Google 官方的 OpenAI 兼容地址。自定义模式可自动探测协议；完整接口地址（如以 `/responses` 结尾）不会再重复追加路径。只在路径或返回格式不匹配时探测其他接口，密钥错误、限流和网络错误会直接显示原因。流式请求可手动开启，单次网络等待默认 90 秒，可调整为 10–180 秒。

OpenAI 官方预设仅指向 `api.openai.com`；旧版强制默认的 `apiznyl.com` 现在单独标为第三方中转，使用它必须填写该站签发的密钥。不同服务商、地域和计费方案的密钥不能混用。程序不会自动从其他软件读取密钥。

连接验证会发送一条简短 JSON 指令，验证通过后才启用 AI 实时对话。仅支持此项目所需的文本面试；不包含各云厂商的专用签名鉴权、音视频或图片生成 API。所有服务商均已做模拟协议测试，真实可用性仍须使用你自己的密钥在本机测试。

### 连接失败排查

| 页面提示 | 修复方式 |
| --- | --- |
| HTTP 401 | 检查密钥是否由当前地址对应的平台、地域签发，是否过期 |
| HTTP 403 | 检查模型权限、服务地区或网关访问限制 |
| HTTP 404 / 405 | 核对 API 地址、协议及控制台提供的准确模型 ID；不要填网页地址 |
| HTTP 400 / 422 | 查看服务信息，核对模型协议；若要求 stream，勾选流式请求 |
| HTTP 402 / 429 | 检查余额、额度和请求频率 |
| 网络连接失败 / 超时 | 检查运行 Python 的电脑的 DNS、代理和证书；可适当增加超时 |
| 服务已连通，但 JSON 验证未通过 | 模型返回了内容但不符合面试要求，换用能遵循 JSON 指令的文本对话模型 |

修改后需重启本地服务并用 Ctrl+F5 刷新页面。旧启动窗口未关闭时，重复双击 `start.bat` 只会打开已有服务，并不会更新进程内代码。关闭 AI 开关会清除后端连接；重新测试失败也会清除旧连接。

协议依据：[OpenAI Responses](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)、[Claude Messages](https://platform.claude.com/docs/en/api/http/messages/create)、[Gemini 兼容接口](https://ai.google.dev/gemini-api/docs/openai)。服务商预设集中在 `app/providers.py`，页面直接使用同一份配置。

API Key 不写入 SQLite、日志或会话记录，只保存在当前服务进程内存中；关闭服务或删除会话后即失效。未配置 AI 或服务调用失败时，应用自动使用本地题库和规则追问继续面试。

## 可审计题库

启动时会把 `data/*_questions.json` 幂等导入 SQLite 的 `question_sources` 和
`interview_questions` 表，并对旧数据库执行增量迁移。当前共 64 道题，其中 33 道为
面向国内面试习惯的原创校准题，17 道根据可追溯的公开候选人面经回忆做最小必要转述，
覆盖项目深挖、Python/AI 工程、RAG、Agent、后端、SQL、统计、数据质量、可视化和业务分析。

每道国产化题目包含难度、题型、频率档、可信度、答案提纲、评分点、常见错误、
核验链接和审核日期。公司题另记录面经发布日期和来源声明，不收录个人信息或整段原文。详细规则见
`docs/question-bank-methodology.md`。

提交岗位信息时可选择目标公司。目前覆盖字节跳动、阿里巴巴、腾讯、网易和美团；生成
面试计划时，系统在岗位和主题匹配的基础上优先选择目标公司的公开面经回忆题，再回退到
通用题库，最后才使用内置基线题。题目页会显示来源类型和可访问的原始链接。

## 自定义题库

首页和资料页都可进入独立题库管理。先新建并命名题库，再粘贴题目或导入 TXT、Markdown、
CSV、JSON、DOCX。导入先生成草稿预览，可以修改题干与主题、补充公司/岗位/来源、删除无关
内容或合并条目；只有点击“确认入库”后，题目才会持久化并参与出题。编号只用于识别题目
边界，题干中的数字、多行条件和代码块会保留。参考答案以独立版本保存，默认标记“未核验”。

同一题可以属于多个题库，每个题库的来源记录分别保留。文字完全相同的题共用稳定内容 ID；
相似题只在预览中提示，不会自动合并。旧版用户题会增量迁移到“历史导入题库”，旧会话仍按
当时保存的题干和来源快照回看。

创建练习时可选择多个题库并调整顺序。普通模式默认安排 6 道主问题：最多 4 道相关、未练的
用户题，再按目标公司题、岗位通用题、内置基线题补足；专项模式只从所选题库选择，最多 6 道，
题量不足时缩短。用户可显式开启重复练习。系统以主问题实际展示作为“已练”依据，并另行记录
是否作答；同一场内始终去重。

主问题和主题分开保存，同一主题可出现多道用户题。在线模型与离线模式都必须按计划题干提出
主问题；模型生成的追问单独标记，不计入 4+2 配额。未核验参考答案只支持表达、结构和证据
评价，技术正确性留空。

题库可通过以下接口检查：

- `GET /api/question-bank`：统计、题型和权威等级；
- `GET /api/question-bank/sources`：来源及许可证；
- `GET /api/question-bank/companies`：已收录公司及各公司的题目数量；
- `GET /api/question-bank/questions?role=ai&topic=rag`：按岗位、主题查询题目元数据。
- `GET/POST /api/user-question-banks`：查看或新建独立题库；
- `POST /api/user-question-bank/import`：生成粘贴内容的导入草稿；
- `POST /api/user-question-bank/import-file`：生成文件导入草稿；
- `POST /api/question-imports/{draft_id}/confirm`：事务性确认入库；
- `GET /api/user-question-banks/{bank_id}/questions`：查看题目、来源和答案版本。
