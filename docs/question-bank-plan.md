# 用户题库完善计划：Grill Me 共识版

确认日期：2026-09-08。状态：题库第一版与面试前体验重构均已实施，并通过自动化与真实页面验收。

本文件记录用户在三轮追问中采纳的 Q1～Q10 建议。它是根目录 plan.md 的题库专项补充；与旧计划在主问题数量、主题组织、原题保留和来源分级上的冲突，以本文件为准。保留现有本地运行方式、会话记录和 60 分钟硬上限。

## 1. 目标与范围

目标是选出贴合目标公司、岗位和用户资料、少重复、有出处的问题。题库总量是辅助指标，不能替代选题质量。

第一版包括：独立题库管理、导入预览与确认、普通/专项模式、用户题优先、来源保留、练习去重。联网补题、语义检索、大规模参考库与自动答案核验放到后续阶段。

用户题的选题优先级与答案可信度分开记录；答案未经核验不能成为降低用户题选题优先级的理由。

## 2. 已确认的出题规则

| 情况 | 行为 |
|---|---|
| 普通模式，相关用户题足够 | 默认 6 道主问题：4 道用户题 + 2 道补充题 |
| 普通模式，相关未练用户题不足 4 道 | 先选现有可用用户题，再以公司题、通用题补足 |
| 专项模式 | 主问题全部来自本场选择的用户题库，不按岗位排除 |
| 专项模式只有 2 道可用题 | 只安排这 2 道主问题，允许追问并缩短时长 |
| 用户题明显不符合岗位 | 普通模式暂不选用并说明原因；专项模式仍可选用 |
| 同一道题同时属于用户题库和公司题库 | 保留两个归属；本场选中了其用户题库时按用户题计算，整场只出现一次 |
| 已经练过 | 默认优先未练题；不足按模式补充或缩短，不自动重复；用户可主动开启重复练习 |

实施默认值：专项模式也以最多 6 道主问题作为首版时长预算；普通模式所有候选来源均不足时同样缩短。没有选择用户题库时继续使用公司题和通用题。补充顺序为公司匹配题、岗位通用题、内置基线题，统一受整场去重约束。

用户选择题库即参与上述优先规则，不再要求额外勾选“优先使用”。支持选择多个题库并调整顺序；题库顺序优先，同库内结合岗位相关性、考点覆盖和练习记录选择。

先选择主问题，再组织主题与时间。同一主题可以包含多道用户题，不能因为旧版每主题只问一道的限制丢失用户题配额。主问题与追问分别计数，追问不用于凑 4+2 配额。

## 3. 原题、来源和评价

- 原题默认保留问法，去除序号不得删改题干中的数字、条件和代码。必要脱敏保留修改说明。
- 原始问题、候选人回忆转述、生成变式分别标记。主问题确定后，在线模型和离线降级路径均须使用该题，不能另生成一道替换。
- 根据简历产生的延伸内容作为“生成追问”，保存其关联主问题和实际问法。
- 每个来源单独保留来源说明、可用的原链接、公司、岗位、面试日期、原文件名及题目所在位置。未知字段留空，不猜造公司或日期。
- 用户提供的参考答案先标记“未核验”；未核验时只评价表达、结构和证据，不给技术正确性分数。
- 已核验答案必须关联核验依据、审核日期及答案版本；只有评价器实际使用对应依据时，才可进入技术评价。不能只改来源等级就宣称评分可信。
- 原题重练不作为平行后测。专项模式无符合条件的不同题目时，不自动生成外部题并称其为用户原题；说明后测题不足。

## 4. 用户流程

1. 新建并命名独立题库，粘贴题目或导入现有支持的 TXT、Markdown、CSV、JSON、DOCX。
2. 提取问题、答案和来源为草稿；保留上下文供核对，不能简单把每行都视为题目。
3. 展示预览，允许修改题干、主题、删除无关内容、合并条目；整批确认公司、岗位等公共信息，单题可覆盖。
4. 确认后事务性入库；未确认草稿不参与出题。无法可靠提取的内容标出并允许手工整理。
5. 在面试资料页选择本场题库、排列顺序、选择普通或专项模式，按需开启重复练习。
6. 准备页展示实际主问题数量、用户题/补充题数量、题库来源和缩短或补充原因。面试前不展示参考答案。
7. 面试按已保存计划提问，报告展示来源与评价依据；后续场次利用练习记录避免重复。

## 5. 数据与兼容设计

沿用 SQLite 和现有接口架构，采用增量迁移。

- 题库：独立 ID、名称、默认公司/岗位、创建时间、排序信息。
- 题目：稳定 ID、确认后的题干、主题、适用岗位、内容类型、版本。
- 题库关联：题库 ID + 题目 ID；同一题可属于多个题库。
- 来源记录：与题目及题库关联，保存原始题干、出处、导入元数据和用户确认信息；合并内容不合并掉来源。
- 参考答案：答案版本、核验状态和依据，独立于题库优先级。
- 导入草稿：批次、预览条目、校验问题、确认状态。
- 练习记录：本地主问题 ID、会话、实际提问和作答状态；未开始的计划不能把题算作已练。默认以主问题实际展示作为去重依据，并区别已作答和未作答。
- 面试计划：模式、选中题库顺序、重复开关、主问题序列、每题的来源及题干快照、选择原因。旧报告按原快照可回看。

相同文字的题自动合并内容并新增关联/来源；相似题只提示用户确认，不自动合并。旧用户题迁入“历史导入题库”，不丢失已存在数据；旧会话仍可读取，缺少可靠题目 ID 的历史不能猜测去重关系。

## 7. 验收场景

| 场景 | 必须观察到的结果 |
|---|---|
| 用户有至少 4 道相关未练题，补充池足够 | 普通模式 4 道用户主问题 + 2 道补充主问题，实际面试与计划一致 |
| 用户有 4 道同主题相关题 | 仍可占满 4 个用户题名额，不被每主题一道的旧逻辑压缩 |
| 专项题库仅 2 道 | 恰好 2 道用户主问题，可追问，无外部主问题 |
| 普通模式仅 2 道可用用户题 | 2 道用户题 + 4 道补充题，补充原因可见 |
| 专项全部已练且未开启重复 | 提示无可用新题，不擅自混入外部题或开始空面试 |
| 用户主动开启重复 | 可再次选择已练题，场内不重复计算同一题 |
| 选择数据分析岗位，导入 Java 题 | 普通模式说明不匹配；专项模式可使用 |
| 用户导入内置题的相同文字 | 内容不重复、来源关联保留，仍可作为用户题入选 |
| 只完成导入预览 | 不产生可用题库条目；确认后才可选题 |
| 原题包含数字、代码、多行条件 | 预览及实际提问完整保留，不被序号清理或逐行拆分破坏 |
| 模型生成首问或切题时试图改题 | 实际主问题仍使用计划题干；生成内容只能成为标记过的追问 |
| 用户题无核验答案 | 技术正确性为空，不以来源优先级或文本长度冒充核验 |
| 重启、再次导入、回看旧报告 | 题库、来源和练习记录保留；重复确认不重复入库；旧报告不受后续编辑影响 |

衡量第一版：满足来源配额的场次数、场内重复题数、实际主问题与计划一致率、可追溯来源比例、导入需人工纠正的条目数。题库条数另行统计。

## 9. 第二阶段：面试前体验重构

第二阶段把 AI 接入提前，并将面试前的准备过程拆成清晰的单功能页面。目标是让用户始终知道当前在哪一步、下一步要做什么，以及哪些条件尚未满足。

页面遵循以下顺序：

1. AI 接入
2. 个人资料
3. 目标岗位
4. 本场题库
5. 面试计划
6. 面试调试
7. 正式面试

页面顶部始终显示步骤索引。已完成步骤、当前步骤和未完成步骤必须有明显但克制的状态区别。用户可以返回已经完成的步骤，修改内容后只让受影响的后续结果失效，不清空无关输入。

每一页只承担一个主要任务，只设置一个突出显示的主操作。次要操作使用弱化按钮或文字入口。不得把 AI 配置、题库管理、设备检测和开始面试堆在同一页。

## 10. AI 接入设计

AI 接入是面试前流程的第一步，默认要求用户接入自己的模型。系统提供的 AI 和本地模式作为次级入口。

默认界面只显示服务商、模型和 API Key。接口地址、协议、流式请求和超时等参数收进“高级设置”，不在首屏展开。连接测试由用户主动触发，避免未经确认地产生请求和费用。

连接成功后收起表单，重点展示模型名称、连接状态和响应时间，并提供“修改配置”。失败时在表单附近说明具体原因和可执行的处理方式，不能只显示“连接失败”。

个人 API Key 只在当前面试会话中使用，不写入长期数据库或浏览器持久存储。可以记住不敏感的服务商、模型和接口偏好。系统 AI 入口弱化展示；本地模式允许用户在没有可用模型时继续完成非 AI 功能。

## 11. AI 在后续页面的职责

AI 在面试前负责辅助理解和推荐，不替代用户确认，也不能突破题库与出题硬规则。

| 页面 | AI 能力 | 用户控制 |
|---|---|---|
| 个人资料 | 从简历或粘贴文本提取经历、技能、项目和优势证据 | 所有提取项均可直接编辑、删除或重新分析 |
| 目标岗位 | 从岗位描述提取职责、必备技能、加分项和面试重点 | 用户确认后才写入本场岗位画像 |
| 本场题库 | 根据个人画像和岗位画像推荐题库、排序并说明理由 | 只做推荐，不自动替用户确认；用户可调整选择和顺序 |
| 面试计划 | 生成覆盖建议、时间分配和选择说明 | 用户可修改计划；最终题目仍受 4+2、专项模式、去重和来源快照约束 |
| 正式面试 | 围绕固定主问题生成追问并理解回答 | 不能改写或替换计划中的主问题 |
| 面试报告 | 总结表达、结构、证据和改进建议 | 无可靠依据时不得生成技术正确性结论 |

简历和岗位描述都允许跳过；缺少资料时使用通用方案，并简短提示个性化程度会降低。AI 分析必须通过明确的“开始分析”按钮触发。分析完成后先进入可编辑的确认状态，再影响题库推荐和面试计划。

AI 对导入题目只处理难以判断的边界、主题和相似关系。原始解析、题干保留、来源记录和事务性入库继续由确定性规则完成，避免模型改写原题或虚构来源。

## 12. 面试前页面与视觉规范

整体界面采用简约、低干扰设计，优先展示当前步骤的核心内容。

- 顶部步骤索引固定在内容区上方，使用短名称，不加入说明段落。
- 每页只保留一个明确标题和一句必要说明；能由控件标签表达的信息不再重复成段解释。
- 主操作固定在页面底部的稳定位置，使用最高视觉权重；返回、跳过、重新生成和高级设置保持次级权重。
- 表单按用户决策顺序纵向排列，不使用大面积双列布局压缩阅读宽度。只有并列比较的信息才使用双列。
- 默认折叠高级配置、来源细节和低频选项，需要时再展开。
- 空状态直接说明下一步，例如“还没有题库，导入题目后可用于本场面试”，同时只提供一个对应操作。
- 状态反馈使用“未开始、进行中、已完成、需要处理”四类统一样式，避免同时出现多套徽标、提示框和说明文字。
- 错误显示在对应控件附近，并给出解决动作；不得让按钮无说明地保持禁用。
- 窄屏和低高度窗口中可以压缩间距，但不能隐藏开始条件、主操作或当前错误。
- 题库页优先显示已选题库、题目数量和顺序。题库管理与导入放入独立页面或抽屉，不与本场选择列表混排。
- 面试计划页重点展示预计时长、题目构成、来源和选择理由；面试前不展示参考答案或冗长评分说明。

文案使用用户能直接理解的动作词，例如“连接我的 AI”“分析简历”“确认岗位”“生成面试计划”“开始全部检测”。删除重复解释、实现细节和对当前决策没有帮助的提示。

- 动画时长控制在约 150～250 毫秒，状态变化清楚即可；长任务的进度动画除外。
- 支持 `prefers-reduced-motion`，用户要求减少动态效果时取消位移、缩放和循环动画。
- 动画不能承担唯一的信息表达；颜色之外还要保留文字、图标或形状状态。
- 步骤条、按钮、弹层、展开卡和上传区必须支持键盘操作，并保持清晰焦点样式。
- 不使用 3D 卡片、视差滚动、粒子、流星、打字机、追随指针、无限轮播等展示型效果。
- 不使用 Webcam Pixel Grid。摄像头调试必须显示未经视觉特效处理的真实画面，避免用户误判清晰度和取景。
- 不把 Floating Navbar、Floating Dock 或大型侧边栏用于步骤索引，以免抢占内容空间或弱化顺序关系。
- 实施前核对所用组件页面及 [Aceternity 许可说明](https://ui.aceternity.com/licence)，只使用许可范围明确的公开素材，并保留必要的来源记录。

最终效果应保留 Aceternity UI 的轻量状态动画和精致边界处理，同时维持本计划要求的单页单功能、少文字、重点明确和低干扰。

## 13. 最终面试调试

“面试调试”是正式面试前的最后一页，只负责验证本场实际会使用的能力。页面由四张紧凑检测卡组成，并提供一个突出显示的“开始全部检测”按钮。

### 摄像头

显示实时本地预览，检查权限、设备可用性和画面是否正常。第一版不录制视频、不上传画面、不进行表情、视线或情绪分析。

摄像头默认是开始条件。检测失败时先阻止开始并给出修复建议；用户可以通过明确的二次确认选择“无摄像头继续”。选择结果只对本场有效，正式面试中显示无摄像头状态。

### 麦克风

显示实时音量反馈，检查权限、设备和有效声音输入。麦克风必须通过才能开始语音面试；检测失败时按钮旁必须显示未满足的条件和修复入口。

### 语音识别

要求用户朗读一条简短测试语句，并实时展示识别文本。第一版优先使用浏览器语音识别；识别不可用或测试失败时，允许自动切换为文字输入，不因此阻止面试。

### 大模型

使用与正式面试相同的连接配置和请求路径，发送一段不含简历、题库和真实回答的合成测试数据。检测响应时间、结构化输出、评价字段和追问字段是否可用。

AI 模式下，大模型检测必须通过才能开始；失败时提供“修改 AI 配置”和“切换本地模式”。本地模式跳过大模型检测，并清楚显示本场不会使用 AI 追问和 AI 报告。

## 14. 调试状态与开始规则

每个检测项只使用四种状态：未检测、检测中、通过、需要处理。页面顶部显示总体进度，检测卡内部只保留结果和对应操作。

默认开始条件如下：

- 摄像头通过，或用户已经二次确认无摄像头继续。
- 麦克风通过。
- 语音识别通过，或系统已经切换为文字输入。
- AI 模式下大模型通过；本地模式下明确跳过。

“开始正式面试”只在条件满足后启用。未满足时必须在按钮附近列出具体条件，例如“请允许麦克风权限”，不能让用户猜测禁用原因。检测结果在本场会话内保留，返回前面页面时不重复检测；修改 AI 配置后只让大模型检测失效，更换输入模式后只重检相关设备。

## 15. 第二阶段实施顺序与验收

### 第一步：页面骨架和步骤状态

建立七步页面结构、顶部索引、前后导航和状态保留。先完成单页单功能布局，再迁移现有表单，避免在旧页面上继续叠加模块。

### 第二步：AI 前置和资料分析

移动 AI 接入，落实个人 Key 优先、会话级保存、系统 AI 与本地模式入口。增加简历和岗位的主动分析、可编辑确认及失败降级。

### 第三步：AI 辅助题库和计划

增加题库推荐理由、排序建议和计划覆盖建议，同时继续由后端硬规则决定合法题目序列。AI 失败时仍能使用现有确定性选题逻辑生成计划。

### 第四步：面试调试

实现摄像头预览、麦克风音量、浏览器语音识别和合成大模型请求。集中计算开始条件，所有失败状态均提供可执行的处理入口。

### 第五步：整体视觉收敛与验收

统一标题、按钮、状态、间距和响应式行为，删除迁移后残留的重复文案和隐藏式前置条件。使用真实页面尺寸检查普通桌面、窄屏和低高度窗口。

验收必须覆盖：

| 场景 | 必须观察到的结果 |
|---|---|
| 首次进入 | 第一项核心配置是“连接我的 AI”，高级参数默认折叠 |
| 个人 Key 连接成功 | 配置表单收起，只显示模型、状态、延迟和修改入口 |
| 没有 AI | 可选择系统 AI 或本地模式，不会卡在空白或无解释的禁用按钮上 |
| 简历或岗位缺失 | 可跳过并生成通用方案，个性化降低提示简短明确 |
| AI 提取错误 | 用户可直接修改每个结果，修改后用于后续推荐 |
| AI 推荐题库 | 展示推荐理由，用户可改选和调整顺序 |
| AI 计划越过题库规则 | 后端拒绝非法结果并使用确定性规则生成合法计划 |
| 摄像头正常 | 显示本地实时预览，不上传或分析画面 |
| 摄像头失败 | 首次阻止开始；二次确认后可无摄像头继续 |
| 麦克风失败 | 明确指出权限或设备问题，不能开始语音面试 |
| 语音识别失败 | 自动提供文字输入模式，其余条件满足后可以开始 |
| 大模型失败 | AI 模式不能开始，可修改配置或切换本地模式 |
| 本地模式 | 跳过模型检测，明确本场缺少的 AI 能力 |
| 低高度窗口 | 步骤索引、失败原因、开始条件和主按钮仍然可见 |
| 返回修改资料 | 只让依赖该资料的推荐和计划失效，无关输入及设备结果保留 |

第二阶段完成后，以面试前完成率、AI 连接成功率、调试一次通过率、禁用按钮原因可见率、从进入到开始面试的耗时，以及用户返回修改的次数评估效果。
